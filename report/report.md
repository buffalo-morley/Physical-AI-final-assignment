# PAI最終課題 説明資料

## 1. 課題概要

本課題では、ロボットシミュレータ [Genesis](https://genesis-embodied-ai.github.io/) 上に構築した
Franka Panda 7軸アームに対して、**自由形式の自然言語指示**でPick & Placeタスクを実行させる
システムを実装した。ロボットは「赤いブロックを緑のエリアに置いて」のような日本語の指示や、
色名を直接含まない「一番右のブロックを一番左のエリアへ運んで」のような空間的な表現、
さらに英語の指示も、AWS Bedrock経由のClaude (Haiku 5.5) を用いてリアルタイムに解析し、
対象ブロックと目標エリアの組を特定した上で、物理シミュレーション内で実際にブロックを
掴んで運ぶ。

## 2. 目的

- ハードコードされた固定シーケンスではなく、都度与えられる自然言語の指示に応じて
  行動を変える「指示理解ロボット」を、実機ではなく物理シミュレータ上で実現すること。
- ブロックを瞬間移動（テレポート）させるのではなく、グリッパーの指と対象物との
  摩擦接触による**物理的に妥当な把持**を行い、搬送中も物理法則の中で安定して
  保持されることを確認すること。

## 3. システム構成

| 要素 | 使用技術 |
|---|---|
| シミュレータ | Genesis 1.4.5（GPUバックエンド, NVIDIA RTX 3090） |
| ロボット | Franka Emika Panda（7軸アーム＋平行グリッパー、Genesis同梱MJCFモデル） |
| AI（自然言語理解） | AWS Bedrock経由 Claude Haiku 5.5（推論のみ、学習なし） |
| 動作生成 | Genesisのinverse_kinematics APIによるIK、直交空間ウェイポイント補間 |

### タスクの流れ

1. 手前の列に赤・緑・青のブロック（4cm角）を3つ、奥の列に赤・緑・青の目標エリア
   （色付きパッド）を3つ、Franka Pandaの作業範囲内に配置する。
2. `commands.json` に記述された自然言語指示を1件ずつClaudeに渡し、
   `{"object_color": "...", "target_color": "..."}` という構造化アクションへ変換する。
   このときシーンの配置情報（手前の列・奥の列の左右順）もプロンプトに含めることで、
   色名を直接含まない空間表現（「一番右」「真ん中」等）も解決できるようにしている。
3. 解析結果に基づき、ロボットが対象ブロックの位置へIKで接近し、指を閉じて把持、
   持ち上げ、目標エリアの上まで搬送し、下降して指を開いて静置する。
4. 全指示を実行したあと、スクリプトにより全ブロックを初期位置へ戻す（後片付け動作）。

## 4. 工夫した点

### (1) AIの活用方法

本課題でAIを使う必須要件に対し、単に「決まったキーワードを検出する」のではなく、
実際のLLM推論API（AWS Bedrock経由のClaude）をロボットの行動決定に組み込んだ。
色名を直接指定する指示だけでなく、位置関係に基づく曖昧な指示や英語の指示も扱えるように
システムプロンプトを設計し、指示が解決不能な場合は `null` を返させて安全側に倒す
（実行前に検証し、無効な指示は実行しない）設計にした。

### (2) 物理ベースの把持と、搬送中に把持が外れる問題への対応

開発初期には、ブロックを持ち上げた直後は把持できていても、目標エリアまで横方向に
大きく移動させる途中でブロックが滑り落ちてしまう問題が発生した。これは以下の2つの
要因を切り分けて解決した。

- **関節空間での単純な線形補間の限界**: 開始姿勢と終了姿勢のIK解だけを関節空間で
  線形補間すると、途中の手先の軌道・姿勢が大きく乱れることがある。これを避けるため、
  直交座標空間上で始点から終点までを複数のウェイポイントに分割し、各ウェイポイントで
  個別にIKを解き直す（直前の解を初期値として与えて連続性を保つ）方式に変更し、
  手先の姿勢を常に下向きに保ったまま移動できるようにした。
- **把持力の不足**: グリッパーの指のPDゲイン（kp）とブロックの摩擦係数が低く、
  横方向の加速に耐えられなかった。指のkpを100から1200に増加させ、ブロックの
  摩擦係数を明示的に2.0に設定することで、搬送中も安定して把持できるようになった。

この問題と対応は、シミュレーション上での検証（把持前後・各ウェイポイントでの
ブロック座標のロギング）によって再現・特定した。

### (3) 動作後の原状復帰

全指示の実行後、ロボットが自律的にすべてのブロックを初期位置へ戻す。これは
タスクの完結性（実世界での「後片付け」に相当する実用的な振る舞い）を示すための
追加実装であり、LLMではなくスクリプトで決定的に行っている（AI要件はPick & Place
本体で既に満たしているため、ここでは再現性と検証可能性を優先した）。

## 5. 実用性・今後の展望

今回はシミュレータ上の色付きブロックで検証したが、同じ構成（自然言語→構造化アクション
→IK/物理把持）は、実際の倉庫・工場でのピッキング作業において「このラベルの箱をBレーンへ」
といった自然言語指示によるロボット操作に応用できる可能性がある。また、現在は固定カメラに
よる色認識を前提としているが、物体検出・セグメンテーションモデルと組み合わせることで、
事前に座標を与えずカメラ画像から直接対象物を特定する拡張も考えられる。
